# Live Character

**让你的 Live2D 角色，成为与你一起工作的桌面伙伴。**

Live Character（LC）是一款运行于 **DeepSeek Harness（DSH）** 的 Live2D 桌面角色插件。它将模型演出、触摸互动、文字对话、语音与口型连接起来，让你用自己的角色和性格设定，建立一个可以在桌面上持续交流的伙伴。

LC 不预设固定的情绪维度或好感度路线。模型结合角色性格、会话、事件时间与近期经历，自行判断这一刻怎样回应，再由插件执行台词、表情与动作。

> **当前版本：0.12.36 · beta版本 · Windows x64**  
> 主功能需要保持 DSH 运行，并配置可用的对话模型。插件不附带角色皮套或本地语音模型权重。

## 环境与安装

### 使用前准备

| 项目 | 要求或说明 |
| --- | --- |
| 操作系统 | 当前发行包面向 Windows x64。macOS、Linux、Windows ARM 尚未完成支持与验收。 |
| DSH | 使用支持插件管理、桌面侧栏与会话能力的 DSH Desktop；具体兼容情况请结合发行说明与内测反馈。 |
| 对话模型 | 在 DSH 中配置可用模型。LC 不限定必须使用 DeepSeek 提供商；图像输入和推理等级能力依所选模型而定。 |
| Live2D 模型 | 自行准备有使用授权的运行时模型 ZIP；必须包含 `.model3.json` 及其引用的 `.moc3`、贴图。 |
| 网络 | 使用云端对话、AI 适配和云端语音时需要。通用运行依赖可从完整安装包本地修复。 |
| 语音 | 可选。使用云端服务需要对应密钥和音色；本地语音目前需要额外运行兼容服务。 |

渲染使用本机图形能力，实际开销受模型复杂度、贴图、物理与帧率影响。目前没有覆盖广泛设备样本的统一最低显卡结论。**普通云端 AI／TTS 使用不要求本地运行大语言模型；本地 TTS 的显存需求需按具体引擎另行评估。**

### 安装与首次启动

1. 从本仓库 **Releases** 下载完整的 `live-character-0.12.36.tgz`，通过 DSH 插件管理安装。
2. 重载或重启 DSH，打开侧栏 **Live Character**。
3. 默认先显示启动页面。点击启动角色，按提示阅读 Cubism Core 许可并进行依赖校验。
4. 如依赖缺失或损坏，使用本地“一键修复”，完成后再次启动。若安装包本身缺少运行依赖，请重新取得完整包。
5. 在角色预览中导入模型 ZIP，选择新建角色或添加到已有角色。
6. 填写性格设定，按需执行参数、触摸与口型适配；AI 适配会消耗模型 tokens。
7. 如需朗读，在“语音与口型”选择服务商、填写相应字段并试播。

自动启动默认关闭，可在“设置”中勾选启用。关闭设置侧栏不会自动退出已运行的桌面角色。

完整发行包包含 Electron 45.2.3、Windows x64 嵌入版 Python 3.13.9、未经修改的 Cubism Core 06.00.0001，以及渲染所需资源。普通用户无需另行安装 Node、Git、Python 或 pip 模块。**这些通用依赖不包含本地语音大模型及其推理环境。**

依赖校验保留文件哈希与运行自检；修复从包内资源恢复，不通过任意外部下载地址替换依赖。

### 模型文件要求

请导入 Live2D **运行时导出文件**，不是仅有 Cubism 编辑工程的文件包。模型所引用文件应保留原始相对路径。

- 必需：`.model3.json`、对应 `.moc3`、贴图。
- 可选：物理、动作、表情、参数说明及 VTS 映射文件。
- ZIP 中有多个模型入口时，可在确认页选择需要导入的入口与名称。
- VTube Studio 并非 LC 基础运行的前置程序；VTS 映射文件可作为适配参考。
- 不同模型的绑定规范差异较大，自动适配后请检查触摸、动作和口型结果。

## 功能介绍

### 桌面角色与快捷操作

角色以透明窗口显示。常用功能通过轻量图标访问：对话、锁定、专注、置顶、音量、窗口调整、AI 总开关与模型切换；完整设置位于 DSH 侧栏。

| 操作 | 默认行为 |
| --- | --- |
| 鼠标左键 | 在触摸区域进行角色互动。 |
| 鼠标右键拖动 | 调整角色在窗口内部的位置，窗口本身不移动。 |
| 鼠标右键点击 | 打开简化菜单，可进入设置。 |
| 窗口调整模式 | 暂停角色鼠标互动，显示窗口边界，调整窗口位置和尺寸，并提供对齐吸附。 |
| 锁定模式 | 透明区域鼠标穿透，保留操作 UI 和触摸区域交互。 |
| 置顶 | 将桌面角色窗口保持在普通应用窗口前方。 |

可在设置中调整鼠标操作方式。置顶不覆盖系统安全桌面等特殊窗口。

### 角色与模型分开管理

**角色**保存身份、性格、会话和经历；**模型**是这个角色当前使用的外观与绑定。

- 一个角色可拥有多套模型，例如同一人物的不同服装与形象。
- 添加或切换同角色模型，延续该角色的 DSH 会话和记录。
- 不同模型分别保存参数、触摸、口型、跟踪及渲染位置等配置。
- 切换到另一个角色时，使用另一个角色自己的会话与记录。
- 删除模型与删除角色区分处理，并提供确认流程；角色删除会关联处理其会话归档。

当前支持建立多个角色，但**一次运行一个桌面角色**。暂不提供多个角色窗口同时自主交流。

### 参数、动作与自动适配

LC 按当前模型读取可用参数、动作和表情，提供可隐藏的模型参数侧栏。AI 参数适配用于建立该模型的可用演出映射；触摸适配与口型适配分别保存，便于独立检查与重新调整。

演出可以组合视线、头部与身体倾斜、表情、配饰、原生动作和模型支持的精细参数。是否能吐舌、鼓脸或使用某种嘴型，取决于模型实际拥有的参数与绑定，插件不会凭空创造模型没有的变形。

支持原模型物理、基础循环、跟踪、呼吸循环及相应自定义。动作与状态按配置处理，避免将所有表情和配饰都作为一次性播放动作。

执行前会核对当前模型的参数与动作，无法使用的指令会给出反馈。**AI 适配不是重新绑定模型，也不是对任意皮套兼容性的保证。** 自动结果不准确时，可手动修改后保存到该模型配置。

### 触摸互动与事件合并

触摸区域可绑定模型网格或部位，随角色变形移动。支持查看互动区域、拖动调整位置与大小、重新绑定，以及自定义向外扩展像素。退出调整时，如有修改会提示保存。

AI 触摸适配根据模型和画面分析部位，不固定要求头、尾巴等部位必须存在。自动分析的结果需要用户确认。

连续触摸采用**可配置的防抖合并间隔**，默认 250ms，可调整为 50–5000ms：

- 相邻操作间隔未达到阈值时，继续归入同一组互动。
- 连续点击、长按、滑动及跨区域操作可以合并为一次事件。
- 长按结束后再结算该段操作，减少对模型的重复请求。

合并用于保留一段连续互动的语义，同时降低碎片请求和调用开销。

### 专注模式与自主陪伴

专注模式支持 **开／关／自适应**。自适应根据键鼠活动及配置阈值切换工作节奏，允许调整判定条件与恢复时间。

- 专注时降低自主陪伴频率，并启用相应的输入活动反应。
- 支持头部、身体与眼睛的鼠标跟随，效果取决于模型映射。
- 专注模式内可按空闲时间切换模型支持的脱捕待机；非专注模式不自动进入脱捕。
- 自主陪伴可配置基础间隔、工作频率倍率和每小时自动调用预算；触摸回应另可调整说话倾向。
- 指定对话模型时，推理等级可按任务自适应，并设置最高等级；选择“跟随 DSH”时使用会话当前模型与推理设置。实际可用档位取决于 DSH 和模型。
- 支持一键关闭全部 AI 调用，保留本地设置与渲染操作。

键盘监测统计输入活动与节奏，**不读取键入正文，也不是准确的文章字数统计工具**。

### 同一会话中的对话与经历

每个角色对应一个 DSH 会话。文字聊天、触摸、自主互动及模型变化，都通过该会话生成回应，便于共享上下文。

自动事件以明确标注的消息进入会话，携带事件来源、时间与必要状态，不伪装成人工输入。DSH 原始历史中可能看到自动事件 JSON 和结构化演出输出；LC 界面将其解释为台词与动作。

提示内容按层级组织：系统层处理通用输出与行为规范；运行时注入提供人格、当前模型能力、语音规范等信息；本次消息承载当前对话或事件。会话历史与即时状态不作为永久不变的角色规则。

LC 另行保存结构化经历，包括事件时间、执行结果、回复和必要诊断，并按需要取用相关内容。它有助于维持连续交流，**不等于已经接入全部第三方记忆插件，也不保证无限长度的长期记忆**。

### 形象认知

在首次创建角色并导入模型、为同一角色新增模型、切换已有模型后，可以触发一次与形象变化相关的互动。

支持图像输入时，向会话提供的是**当前角色画布**，用于观察角色外观，而不是截取整个桌面。回应应自然地融入换装体验，而不是逐项朗读图像说明。模型不支持图像输入时按可用元数据处理，无法获得相同的视觉认知效果。

### 对话界面

- 桌面模式提供底部半透明输入 UI，可开关、发送文字与停止当前生成。
- 台词以对话气泡展示，尽量保持在角色头部上方，并进行边缘避让。
- 气泡按台词长度适配，支持逐字渐显、阅读速度、停留时间与外观设置。
- 开启语音时，台词等待音频开始，并按播放时长和阅读停留时间展示。
- 完整对话记录通过弹窗查看，带时间记录，可滚动浏览。

### 余额提醒

可利用 DSH 提供的 DeepSeek 余额能力，按自定义阈值与检查间隔，通过角色台词气泡提醒。可调整提醒文案与显示方式。

这不是所有模型服务商或语音服务商的统一余额查询，也不等同于完整账单统计。

## 语音与口型

### 当前语音入口

| 来源 | 当前接入范围 | 需要准备 | 状态说明 |
| --- | --- | --- | --- |
| Breeze 云端 | `breeze-tts-2`、`breeze-tts-2-multilingual` | API Key、音色 ID、相应接口 | 已实现专用请求适配；可接收本轮演绎指令。 |
| Fish 云端 | `s2-pro`、`s2.1-pro`、`s2.1-pro-free` | API Key、对应音色引用 | 已实现专用请求适配；依服务商格式发送模型与音色字段。 |
| Qwen 云端 | 百炼 `qwen3-tts-flash` 非实时 HTTP 语音 | 对应地域密钥、支持的音色 | 已实现该接口范围；不代表全部克隆、设计音色及实时型号都可用。 |
| 自定义语音 API | 实际兼容 OpenAI Speech 协议的服务 | 正确的合成地址、模型与音色 | 通用入口；服务必须确实兼容协议。 |
| 本地 HTTP 语音 | Breeze 本地／通用兼容服务入口 | 已自行启动的本机推理服务 | 部分接入能力已有，后台引擎托管未完成；当前限制为本机回环地址。 |
| IndexTTS、AuK-Flash 等本地引擎 | 本地方案与适配方向 | 各自模型及运行环境 | 不作为已完成可用的云端服务商，不能仅填名称即运行。 |

接口已实现不代表所有账号、音色、地域与服务版本均完成真实付费测试。服务商更新协议后，可能需要调整适配。

### 配置与密钥

选择服务商后，按页面对应字段填写。**音色 ID、密钥 ID 与 API 密钥不是同一个概念**；应使用服务商实际用于请求鉴权的密钥。

LC 不以密钥前缀代替云端鉴权。保存仅进行本机写入；连接测试与语音试播才访问服务。某些密钥权限可能允许合成、但不允许管理查询，因此“查询失败”不必然等于“合成无权限”，请结合具体错误判断。

密钥在支持的 Windows 加密存储环境中长期保存，并按服务商与接口区分。密钥仍可能被服务商撤销或到期；更换设备需重新配置，配置导出不包含密钥。

### 演绎与播放同步

角色可以在同一轮输出台词与演绎意图。LC 按服务商实际支持的字段组织请求，避免把某一家专用提示词原样塞入所有 API。

当前流程是**取得完整合成音频后再播放**，同步台词气泡、逐字动画与口型。演绎程度依赖服务商、音色和文本本身；这不保证所有服务都有相同的情感控制能力。

桌面音量按钮可调整音量与静音；静音暂停朗读和后续语音调用。停止本地播放或会话生成，不保证撤销云端已经受理的合成任务与计费。

### 独立口型配置

口型适配与演出参数适配分别管理，按当前模型保存：

- 默认开口、嘴形参数。
- 模型实际具有的 AIUEO 嘴型。
- VBridger 相关嘴型与变形参数。
- 口型强度、时间偏移和映射范围。

口型强度与偏移调整后在本机保存，重启保留，包括强度为 0 的设置。音频播放时，部分不兼容的细嘴型表情会让位给口型驱动。

当前主要使用真实音频的频谱特征近似驱动，或使用导入的口型时间轴。**没有捆绑官方 MotionSync／OVR 音素分析引擎，也不能保证逐音素的 AIUEO 精确识别。** 模型缺少相应参数时，只能使用已有映射。

动作随语音安排时序，但原生动作仍按作者制作的速度播放，必要时保持末帧；这不是对原生动作文件进行任意慢放或无缝循环。

支持调整主要分栏大小。辅助说明尽量收进悬浮注释；需要消耗 tokens 的 AI 功能保留直观提醒。

### 资产与配置分层

默认运行与数据根目录为 `%LOCALAPPDATA%\LiveCharacter`。角色资产位置可在设置中自定义；Core、运行库、日志与部分本机偏好不随角色资产目录一起移动。

下表路径相对于角色资产根目录 `asset`：

| 路径 | 内容 |
| --- | --- |
| `_characters/<角色ID>/character.json` | 角色身份、名称、性格及模型列表。 |
| `_characters/<角色ID>/models/<模型名>/` | 模型运行文件，保留相对引用。 |
| `_characters/<角色ID>/memory/` | 会话关联、对话、状态与结构化经历等记录。 |
| `_characters/<角色ID>/settings/character.json` | 角色级设置。 |
| `_characters/<角色ID>/settings/models/<模型配置>.json` | 模型参数、触摸、口型及渲染相关配置。 |
| `voice-models/` | 本地语音资产预留位置；放入权重不会自动启动推理。 |

### 配置导入与导出

入口为 **设置 → 配置备份**。可保存既有角色设置、对应模型的参数、触摸及口型校准等信息，并在导入时进行角色／模型归属检查。

**配置备份不等于完整数据备份：**不包含模型素材、Cubism Core、运行库、API Key，也不替代对话和记忆目录备份。部分本机全局偏好不属于该导出范围。跨设备使用前需先准备相应模型，并重新设置服务密钥。

升级或删除角色前，建议单独备份角色资产目录与重要会话。插件不自动迁移早期 `DSHWritingPet` 目录。

## AI 调用与隐私

| 场景 | 处理内容与范围 |
| --- | --- |
| 聊天、触摸、自主互动 | 事件及相关上下文通过 DSH 发送给所选模型。 |
| 形象认知、AI 适配 | 可能发送当前角色画面、模型参数及相关素材；属于 AI 调用，会消耗 tokens。 |
| 云端语音 | 台词及服务需要的演绎信息发送给所选 TTS 服务，可能单独计费。 |
| 输入活动监测 | 用于活动节奏判断，不收集键入正文。 |
| 前台进程感知 | 默认关闭；启用后使用可执行文件名，不读取窗口标题、文档正文或全桌面截图。 |
| 保存设置与依赖修复 | 正常本机保存、离线校验与修复不调用 AI。可选 AI 诊断需另行触发。 |

自动互动频率、每小时预算、推理等级上限、语音开关及 AI 总开关可用于控制调用。DSH、模型商与语音商分别适用各自的数据处理和计费规则。

提交诊断前，请删除密钥、个人路径中不愿公开的信息和私密对话。不要上传无再分发授权的皮套或音色。

## 扩展接口

LC 提供 `liveCharacter` 服务，包含以下协作入口：

| 入口 | 用途 |
| --- | --- |
| `state()`、`on()` | 查询状态、订阅 LC 事件。 |
| `registerContext()` | 为相关互动提供附加上下文；支持事件信息与作用范围。 |
| `onReply()` | 观察聊天、触摸、自主观察与模型变化等回复。 |
| `experience.query()`、`experience.subscribe()` | 查询与订阅 LC 结构化经历。 |
| `perform()`、`showBubble()` | 请求受校验的动作、视线与台词展示。 |
| `registerSettingsLink()` | 注册相关设置入口。 |

这些是扩展基础，不是“安装任意记忆、IM 或语音插件即可自动联动”的承诺。第三方插件是否参与原生 DSH 会话，还取决于其自身挂钩方式、作用域与权限；需按具体插件联调。LC 经历接口目前不提供任意外部写入。

- 真正的低延迟流式 TTS、完整语音打断与实时角色语音接口。

### 本版验证情况

当前版本完成 **141 项 Node 测试与 25 项 Python 测试，共 166 项自动化检查**，并进行设置界面与组件检查。自动化主要覆盖协议、状态、配置、适配与演出逻辑，不代表全部硬件、Windows／DSH 组合及付费语音服务均通过端到端验证。

- 云端接口与音色能力可能随服务商更新而变化。

## 常见问题

**一定要用 DeepSeek 吗？**  
不一定。DSH 是运行宿主，LC 可使用 DSH 中支持的模型。视觉、推理等级与其他能力受所选模型约束。

**需要安装 VTube Studio 吗？**  
基础使用不需要。模型的 VTS 参数或表情映射可作为参考，但不保证完整复现 VTS／VBridger 的全部追踪行为。

**为什么触摸和自主互动会出现在 DSH 会话里？**  
它们需要与文字聊天共享上下文，因此采用明确标注的自动事件消息。它们是系统产生的事件，不代表用户手动输入。

**换一套衣服，会忘记之前聊过什么吗？**  
把新模型添加到原角色，再切换模型，会延续该角色的会话。新建另一个角色则使用另一套角色记录。

**可以完全离线使用吗？**  
本地渲染与部分交互可以；AI 对话和适配取决于 DSH 所接模型，云端 TTS 需要联网。内置通用依赖不代表已内置离线 AI 或语音引擎。

**本地语音模型放到 `voice-models` 后为什么没有声音？**  
该目录不会自动加载任意模型权重。目前仍需运行兼容的本机语音服务，再配置连接；一键后台运行正在作为后续方向讨论与开发。

**模型一直没有某种表情或嘴型，是坏了吗？**  
先检查皮套是否拥有对应参数、映射是否正确、参数是否被其他演出层覆盖。AI 能调用已有变形，不能补出未制作的模型能力。

**API 设置保存成功，就说明服务已经可用了吗？**  
不是。保存成功只表示本机配置写入成功；请分别进行连接测试与语音试播，并查看服务返回的具体错误。
