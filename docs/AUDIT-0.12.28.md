# Live Character · 0.12.25 之后逐项自检

日期：2026-11-12。核对基线：已交付的 0.12.25、0.12.26、0.12.27 源码/反馈，以及用户后续明确的要求。修订版本：0.12.28。

## 结论

0.12.27 并不是所有目标都完成：它已有音频近似口型，但没有独立的逐模型口型配置；触摸事实混在本地历史中，缺少独立经历记录与查询；原生 DSH 续聊回流只显示/朗读，没有执行完整参数计划。以上已在本轮补齐，不能把之前测试通过等同于这些需求原本已实现。

同时仍有宿主接口边界和待实机验收项，见后文。旧版本记录不迁移、不回填，没有使用内部 Session.append，也没有新增固定情绪坐标。

## 本轮修订说明

### 独立口型配置

位置：**语音与口型 → 当前模型 · 独立口型适配**。

有「重新自动识别」「AI 口型适配」「保存口型配置」「新增口型绑定」。每条绑定可选真实模型参数和音频输入，编辑输入/输出范围、中立值及 linear/centered 映射，单独禁用或删除。已有 VTS 映射可包含反向输出和不同数值范围，不套全角色统一数值。

配置按角色下的具体模型保存，同角色 A/B/A 皮套各自复用；配置导出包含 mouth 字段，旧配置没有该字段时保持当前模型设置。语音来源、总体口型强度和时间偏移仍沿用原角色偏好，映射本身独立。

AI 适配是用户主动点击的独立作业，沿用冻结/遮罩与恢复流程，直观标明 tokens；不会每次启动要求更新。无可验证结果保留旧配置。自动识别和手动编辑不调用模型。

核心实现：lab/mouth-profile.js、lab/speech-core.js、lab/studio.js、desktop/library.cjs、lab/portable.js。

### 经历记录与连续记忆

路径：当前角色资产目录下 **memory/experiences.v1.jsonl**，不以模型文件名当身份。

事实与后续投递状态分别追加，不覆盖最初事件。内容包括 eventId、characterId、profile、sessionId、occurredAt、recordedAt、事件 payload，及可用的 sessionSeq、自由情绪、speech 指令与回复缓存。状态区分 occurred/queued/submitting/completed/skipped/failed/cancelled/unknown；unknown 不代表可以再生成一次。

成功完成后，后续气泡等显示错误不改写其为失败。没有台词的完成也保留；取消、过期和额度跳过可诊断。模型忙碌重试不会建立第二个事件。

当前会话近期经历进入后续 LC 请求，限制数量与长度，保留较新的事实；全量记录保留在文件中，不把所有原始历史反复塞入提示词。情绪保存其来源事件/会话引用。

只读接口：

```js
const page = await liveCharacter.experience.query({
  sessionId, // 可选，默认当前会话
  types: ['touch', 'model_change'], // 可选
  limit: 50
});
const stop = liveCharacter.experience.subscribe(change => {
  // change 含事件编号、归属与状态。需要详情时再 query。
});
```

默认只查当前角色当前会话；includeArchived:true 可显式读同角色旧会话。重置保留归档事实，但不会自动作为新会话近期记忆注入。禁止查询其他角色归属，不开放第三方 append。

仅记录升级后的新 LC 事件及实际收到的原生回流，不回填旧历史。它不是 DSH 离线消息的全量镜像，不是已安装的长期摘要/向量记忆引擎；第三方记忆提供方仍需遵守当前 session 和重置语义。

核心实现：desktop/experiences.cjs、desktop/library.cjs、desktop/main.cjs、lab/companion.js、host-panel.js。

### 同一会话与演出

原生回流现在保留结构化计划，包括 text 为空的静默计划；按当前角色 rig 校验 pose/fine/keyframes、表情与动作，然后进入演出。语音启用时沿用同一声音播放时钟启动表现；不因只读订阅重新触发生成。

角色契约仍用固定 required context，不依赖未公开 agent 参数、不 complete 覆盖其他系统段。每次 LC 请求携带实际人格、当前能力和状态。DSH 直接续聊参考最近一次 LC 快照；在 LC 刚改人格/换装但尚未提交下一条原生消息时，DSH 快照可能滞后。

原生消息去重现在使用 sessionId + seq；多个 assistant 结果不再取第一条。仍不能根据现有公开反馈证明单条输出的原子归属，这点需要宿主继续答复。
