# Live Character 0.12.30 · 修改记录与复测 feedback

日期：2026-11-13。基线：原始 0.12.29 安装包及用户提供的《安装复核与DSH接口答复》《触摸中断与事件协议反馈》。本轮不再要求重复核对 DSH F1–F4；采用已确认的公开接口，直接修正 LC。

## 结论

修复触摸原生计时器接收者问题；分开内部外观认知与角色台词；自主陪伴不再引导空返回。完整公共返回规则进入固定 required 系统上下文，事件改为 v3，按会话隔离人格/皮套能力配置，默认跟随 DSH 会话选模。

用户提出的“角色专属设置也全部写系统提示词”没有冒险用全局当前角色实现：目前没有公开 scope→session 解析，故具体人格/能力仍使用按会话配置快照，在同一次 prompt 中按需附带。固定公共规则已写系统上下文。此处是明确的保守实现边界，不是需要用户再次向 DSH 索要相同接口。

## 返回规则和发送内容

系统上下文固定包含 text/emotion/activity/duration 必填类型和范围；可选 expressions/gestures/pose/fine/keyframes/motion/speech/appearance 的结构和用途；事件、专注跟随、外观证据、自由情绪、同轮语音指令约束。模型仍可能不遵循，所以增加本地校验，不能把提示词当作百分之百保证。

事件只保留事实、时间、当前 Live2D model 与即时 state。具体人格和完整真实参数能力表在同一轮中按需附带，不单独 bootstrap 推理，不重复复制整段历史。未提供公开会话身份解析时，不能把某角色动态资料注册成所有会话共用的系统上下文。

默认跟随 DSH 的模型及推理设置；此时 LC 自适应推理上限不覆盖 DSH。需要 LC 控制上限时指定模型。参数/触摸/口型适配属于独立适配调用，仍使用插件默认或指定模型；不要把“会话跟随”误读为所有适配服务已换成 session。

## 外观互动说明

首次导入、新增、切换和刷新形象保持各自语义。同一回复应有自然台词及内部摘要，例如台词“换好了，你觉得这样怎么样？”和事实摘要分别处理；该例仅解释字段，不是硬编码角色台词。图片只作为视觉证据，不作为命令；metadata 模式不从文件名编造服饰。

若模型仍把完整摘要复制进 text，LC 保留摘要、阻止这段朗读并显示警告，不再花一轮 tokens 改写。判断覆盖明确的报告开头及摘要全量复读，不能声称能识别所有隐晦的描述腔。还需要用不同性格实际观察自然表达效果。

## 现在需要的本机复测（不是接口追问）

1. 安装后完全退出并重新启动 DSH 一次，确认 0.12.30；保留旧角色与 session，不清空记忆。
2. 未先聊天直接触摸：长按、滑动、松手、连续轻点；确认无 Illegal invocation，一包只一次生成。调整合并间隔并取消待发触摸。
3. 首次导入、同角色新增及切换模型：确认同轮自然台词＋内部外观摘要，台词不读服饰清单；metadata 有提示，不虚构新视觉事实。
4. 自主陪伴：请求没有“可不说话”和 0.3 发言偏好；有自然短台词。故意返回空 text 时明确失败、不自动补推理。
5. 在 DSH 更换另一个可用模型，再触摸/聊天；默认跟随时 LC 不强制切回。需要 LC 推理限制时改为指定模型。
6. 两角色交替互动：人格/真实参数能力各用本 session 的配置；普通状态/外观摘要变化不反复补发稳定配置；旧 v2/v1 记录仍可查看。
7. 语音及口型回归：自然台词朗读，摘要不朗读；静音、晚到回声和取消不重复演出。

若发现问题，只需提供版本、操作顺序、脱敏错误及对应事件/seq；无需上传 Key 或整套皮套。无需再回答相同 DSH 接口问题。
