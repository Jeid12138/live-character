## 内容比重的实际含义

这次分配的是约束优先级、回应中心和补充资料的保留规则。DSH 没有公开“系统占 40% / 用户占 30%”这类注意力旋钮，不能用 token 占比冒充模型的真实权重；上下文 order 和 text part 顺序也不等于优先级数值。

| 层 | 相对作用与比重 | 放置和发送方式 |
| --- | --- | --- |
| A 会话身份/路由 | 隔离前提 | sessionId、workspace、preset 由宿主/路由管理；不用大段重复身份限定词 |
| B 固定公共契约 | 硬约束 | 固定 required systemPrompt.context；完整 JSON 字段/范围、能力、证据及演出规则；无动态历史/状态/LLM 名称 |
| C 完整角色/模型配置注入 | 主要配置载体，可以是内容大头 | lc.context.v1 按会话、版本附带：人格、当前皮套、真实参数/动作/范围、独立口型映射、所选音频模型/固定演绎设定/调用格式；不能改公共 JSON 契约 |
| D 当前用户原话/事件 | 本轮回应中心 | lc.event.v3 的 data，保留真实输入；本轮最后一个 text part；不被旧摘要或进程信息抢主题 |
| E 即时状态/模型 | 当前事实辅助 | state/model，供情绪延续、专注和本地控制判断；不是固定情绪剧本 |
| F runtime 参考注入 | 注入层中的辅助子类，不等于全部注入 | 有来源的第三方资料、有限检索、进程名；有内容才发，不当新命令 |
| G 会话历史 | 保留关系和经历连续性 | 交给 DSH 原生历史；不重复复制全部旧消息，不用新状态改写过去 |
| H 结构化经历账本 | 完整事实存档 | 本地 append-only，只读 query/subscribe；不整本塞入 prompt |
| I 记忆/上下文插件 | 按需提取补充事实 | 接通的 hook/query 提供有来源资料；不默认拥有 system 权限，不保证任意插件自动兼容 |

C 的目标仍是 session-scoped 系统配置，但当前公开接口没有安全的 scope→session 解析，所以保持同轮配置块。反馈中“角色身份已由系统提示词承担”的说法需限定：公共规则只知道配置的用途，具体人格/能力实际仍来自本会话配置，不能写成已经全部进入系统。注入层不再只是人格卡：现已纳入完整皮套能力、独立口型映射和音频设置。口型实时输出仍由本地音频控制；映射配置放 C，原始音频字节/全量时间轴不塞进系统提示词。

## 字节预算与删减顺序

继续使用事件 8KiB 硬上限、配置 48KiB、runtime 8KiB；这是容量边界，不是各层注意力权重。普通触摸 1.5KiB 是目标，部位汇总较多时仍以事实完整和 8KiB 硬上限为准，不承诺任何触摸都≤1.5KiB。

必要格式不因精简而删除；人格和真实参数 ID/min/max/neutral 只在首次、配置变化或既有检查点附带；普通状态变化不重发整表。当前用户原话不静默裁切，超限明确拒绝。触摸先压缩路径并保留部位汇总；runtime 超额先剔除尾部、低优先级提供方资料，再削减检索项，标记 truncated。现有 provider priority 是资料保留顺序，不是让插件获得更高指令权限。

同一轮在宿主组装的系统规则及既有历史仍可能计 tokens；配置不重复附带也不代表宿主历史免费。没有制造固定节省比例或可控注意力数值。

## 完整注入层与音频调用格式

核心配置可以明显大于当前事件，本轮新增测试实际构造超过 runtime 8KiB 的有效配置，确保完整参数与口型不被错当参考资料裁掉。配置上限仍 48KiB，超出明确拒绝；不会为了让用户消息“占比更大”静默删掉皮套能力。

音频注入由当前选项决定，不把所有引擎的文档一起发给模型。包含模型/音色选择、固定演绎设定、统一 text/speech.instructions 的返回约定、实际 adapter 请求结构和文本限制。提供商专属字段只在配置注入中出现，不进入固定系统规则。实际合成仍由 LC 执行，角色不输出 HTTP、Key 或认证头。

| 当前接线 | 注入的实际格式 | 演绎方向是否转发 |
| --- | --- | --- |
| Breeze 云端 | text/model_id/instructions/voice_settings.guidance_scale，音色在路由 | 是 |
| 本地 Breeze | multipart text/instruction/cfg_scale，可带本地 ref_audio/ref_text | 是 |

这些是当前适配器的真实行为，不是所有引擎理论能力的结论。本轮没有改造这些合成器；已有未转发方向的线路不宣称有情绪控制。新 Python 测试直接对照 tts_api.build 的真实输出，防止文档式注入与实际 JSON 字段漂移。

只注入公开设置，排除真实 Key、认证头、私有地址、参考音频字节/文字稿。固定演绎设定及语音/口型设置变化会更新配置版本；静音开关、上一情绪等即时状态不改变配置。通用本地服务的模型名目前没有探测接口，明确“由已连接本地服务决定”，不借用旧 API 模型选项冒充。新增 schema 字段不需要清空旧记录。

## DSH 生命周期和边界

接受已确认的每步组装生命周期：旧 system/message 是历史快照，不能凭旧顶部判断新版是否生效。更新后完整退出并重启一次 DSH，使旧 Agent scope 释放；查看新一步最新 system/message 和新事件。无需卸载角色、清记忆或重建会话。

没有新增/假定 session-scoped context、scope→session、任意 append 或 replyTo 接口；不再为相同缺口反复追问。角色配置尚未进入系统这点保持透明。跨入口精确关联、follow 恢复和第三方实际 hook 兼容边界沿用 .30，未宣称解决。
