## 命名与升级

正式包名、插件 id 为 live-character，界面显示 Live Character，运行和数据根目录为 %LOCALAPPDATA%/LiveCharacter。配置导出文件名为 live-character-config.json，文件格式保持兼容旧导出。

自 0.12.12 起采用新安装标识。从旧 dsh-writing-pet 升级时，先退出旧桌面角色，在 DSH 卸载旧 dsh-writing-pet 包，再安装本包并按提示重载；旧包未移除时可能出现重复预设/侧栏或端口占用。插件管理器若显示 npm 标识，会显示 live-character；是否显示带空格的 Live Character 由 DSH 界面决定。

从 0.12.12/0.12.13 更新到 0.12.30 直接使用当前 LiveCharacter 目录，不需要卸载重建角色。

按此前不再做迁移的决定，插件不自动扫描、移动、复制或删除旧 %LOCALAPPDATA%/DSHWritingPet。新目录是独立测试环境，不会自动显示旧角色、配置和记忆；旧文件仍保留在原位。若要沿用资料，先保留旧目录并单独确定导入方式，不要把整个 assets.json 原样复制到新目录，里面包含旧绝对路径。

依赖可在用户点击启动后的“离线导入”中，手动选择旧 Electron/Python 目录，通过完整哈希校验后复制到新目录，避免重复下载。这个操作不导入角色资料。

新的公开服务名是 liveCharacter；writingPet 仅作为已弃用的同对象别名保留，供已有第三方连接过渡。路由和侧栏统一使用 /live-character 与 live-character.settings，不注册旧路由。

## 安装、校验与依赖修复

完整安装包自带 Python 3.13.9（Windows x64 嵌入版）、Electron 45.2.3（Windows x64）与未经修改的 Cubism Core 06.00.0001；PIXI 与带颜色修正的 Cubism 渲染器也已内置。不要只复制脚本文件，runtime-payloads 是安装包必需部分。

默认加载插件只显示启动页，不运行 PowerShell、不检查或展开依赖、不调用模型。点击启动角色后才校验已安装运行库的完整文件哈希、原生版本和 Python 基础模块，再校验程序文件。启用随 DSH 自启动时，才会自动进入检查流程。

依赖缺失/损坏时提供“一键修复（无需 AI）”：校验包内 ZIP → 本地解包 → 逐文件校验 → 自检。没有运行依赖联网下载或镜像回退。内置 ZIP 也缺失/损坏时，明确提示重新安装完整插件包；离线高级入口仅接受匹配 ZIP/目录。AI 协助仍为可选诊断，会直观提示 tokens 消耗；AI 只选择既定修复/重检/手动处理流程，不执行任意命令或地址。

Core 首次使用仍需用户阅读并同意 Live2D 官方许可，之后从本地安装包修复。Core 固定在 %LOCALAPPDATA%/LiveCharacter/core，不随角色资产保存位置移动。已有匹配运行库只复用，不重复解包；修复完成后等待再次点击启动角色。

准备中可以显式取消；发起准备的 React 组件卸载也会取消。宿主若只是隐藏侧栏，则不能据此保证取消。已经运行的角色不会因为关闭设置侧栏而停止。

程序文件另有 runtime-code-manifest.json：检查包内源码与 app-版本目录的哈希。程序缓存损坏时从包内原子修复；安装包源码损坏时停止并提示重新安装。修复遇到非生成的自定义文件会保留备份，不改动角色和记忆。

完整包无需安装额外 pip/npm 模块。可选本地语音模型/API 不属于通用运行库；目前仍由用户选择语音服务/模型，包内不含未指定的音色克隆大模型权重。

## 角色与模型

角色拥有稳定的 char-UUID、名字、性格、对话和一个 DSH 会话。同一角色可以添加多套模型，添加或切换模型继续使用该角色的会话与记忆。

导入 ZIP 时先选择新建角色或已有角色，再勾选 model3 入口并填写模型名。多个入口默认全选，可以取消。角色选项显示模型数量和最近使用时间；同角色不允许重复模型或重名。确认页须勾选“导入后不可拆分或移动”。如果要让另一个角色使用相同素材，可以从 ZIP 再导入一份。

“切换模型”按角色、模型两级选择。角色卡可改名、添加模型。模型配置分别保存；角色会话、历史和性格不会因为添加模型而重建。导入失败只回滚本次新增或修复的模型，不影响角色已有资源和记忆。

删除模型只删除这一套资源及其参数、触摸配置；最后一个模型需通过删除角色处理。删除角色须再次确认，DSH 会话通过持久队列归档。

## 资产与配置

| 路径（位于 asset 下） | 内容 |
|---|---|
| _characters/<characterId>/character.json | 角色身份、名称、性格与模型列表 |
| _characters/<characterId>/memory | session.json、history.jsonl、state.json |
| _characters/<characterId>/models/<模型名> | 解压的运行时模型，保留相对引用 |
| _characters/<characterId>/settings/character.json | 角色级陪伴、规则、气泡、语音设置 |
| _characters/<characterId>/settings/models/<profile>.json | 模型级参数、触摸、适配报告、跟踪与渲染位置 |
| voice-models | 可选本地语音模型资产 |

角色场景中的模式、表情和手势属于角色；参数锁定、缩放与位置按模型保存。当前模型不存在的参数或动作由校验层拒绝并显示警告，结构化原因记入本地经历。

不再执行旧数据的自动转换、移动、合并或旧通用记忆分配。已有的角色与模型结构直接读取；旧结构请通过导入重新指定角色归属。已有 _legacy 历史备份保持原位，存在时提供打开目录入口。

## 互动与 AI

角色右上角提供对话、锁定、专注、置顶、音量、窗口调整、AI 总开关和切换模型。左键抚摸，右键按住拖动，右键轻点打开设置菜单。专注按钮循环关、开、自适应。锁定后透明区域穿透，按钮与触摸区保留交互。

参数适配和触摸适配分别提供入口，新模型导入可一起适配。适配使用 high，每项一次模型调用；调用 AI 会消耗 tokens。每模型保存独立适配报告和参数含义。

DSH 的每角色独立 Live Character 预设承载聊天及自动事件，同角色换模型继续同一会话。全局工具 allow:[] 保留；scoped 工具和宿主附加上下文不因此自动移除，不能宣称整个 Agent 零工具。

## 其他功能

前台应用感知默认关闭，只传当前可执行文件名。键盘监测只统计次数。语音支持本地服务与兼容 API，音色克隆依赖所选语音服务；音频口型支持导入时间轴。

配置导出包含 characterId。导入旧配置可恢复兼容设置；历史仅在角色身份匹配时恢复，配置导入不会改变模型归属。

记忆增强等插件可通过 liveCharacter 接口提供上下文，回调同时获得 characterId 和模型 profile。资产保存位置可在设置中修改。

## 页面诊断

logs/renderer-last-error.json 记录页面错误、Promise 拒绝、资源/主页面加载失败、preload 错误、渲染进程退出和设置操作的原始错误堆栈。复制诊断会附带当前角色页面的这份诊断；不记录执行脚本文本或调用载荷。模型加载前等待 Core 的公共版本 API 可用，避免 JS load 早于 WASM 初始化。模型 MOC3 格式高于 Core 支持范围时给出明确提示。Core 支持某个格式不等于旧渲染器支持该格式的全部高级混合/离屏绘制特性，需实际模型复测。

## 绘制兼容性

Core 5.x 的 Drawables.renderOrders 与 Core R5 的 Model.renderOrders 都是渲染排序；作者 drawOrders 允许重复和非连续值，不能用于密集数组下标。当前渲染器同时读取前两者，保持 Multiply/Screen 颜色修正。离屏绘制、5.3 高级混合需要完整的新绘制管线；遇到这些模型会在开始绘制前明确提示 RENDERER_FEATURE_UNSUPPORTED，不静默降级。渲染失败会停止帧循环，设置读取仍可用。

## 0.12.30 模型切换与形象互动

演出与渲染页新增切换模型快捷入口，复用原角色/模型选择窗口。桌面普通拖动键（默认右键，支持原鼠标按键交换设置）仅移动画布内角色，保存至当前模型的 placement；轻点仍呼出菜单。窗口移动/缩放仅通过窗口调整模式操作。

同角色切换到不同模型并成功加载后，触发一次 model_change 互动；首次启动、选择同一模型、切换到另一角色不触发。尊重 AI 总开关和自动调用预算；基础自主陪伴开关只控制自然定时陪伴。切换窗口可直观看到 tokens 提示。

同一次互动携带角色截图（只取角色画布，不截桌面），支持图片时将外观摘要记入当前模型配置；不支持图片或附件服务不可用时只使用名称/旧记录，并明确提示没有建立新的视觉认知。不会额外发起一次高推理识图请求。截图在角色 settings/models/<profile>.appearance.jpg，模型摘要保存于 model-appearance-v1；形象事件与回应保存于角色 memory/state.json 的 appearance-memory-v1。删除对应模型会清除其截图。

换装台词沿用气泡、插件对话记录及可选自动语音。后续插件对话会携带当前形象与最近换装经历；DSH 专用角色预设也会按 session.json 找到该角色的持久记录，供主会话下一轮读取。DSH 未公开追加非用户事件/助手消息的接口，因此不伪造用户发言，也不假称写进了原生事件流。插件对话历史继续合并本地回应和原生会话记录。

## 角色会话工作区（0.12.30）

新建原生 DSH 会话前，按公开 workspaceController.create/rename 接口注册或复用 %LOCALAPPDATA%/LiveCharacter/workspace，将组名设为 Live Character，再向 sessionController.create 传 workspaceId。会话标题仍为 Live Character · <角色名>。只有创建真实聊天会话才准备工作区；加载插件和启动角色不触发此操作，也不消耗模型 tokens。

每个插件生命周期只进行一次注册（并发请求共用同一次准备）。跨重载用同一路径幂等复用；名称已经正确时不重复 rename。工作区信息单独记录在数据目录的 session-workspace.json，不改写 assets.json。持久 ID 不直接作为可信归属，以免换 DSH profile 或工作区删除后误用旧 ID。

已有会话继续原 ID、原历史及原归属，不重建、不迁移、不使用排序接口冒充分配接口。删除角色仍仅归档该角色会话，不删除工作区。没有指定 cwd，需在真实 DSH 检查 workspaceId 是否足以建立分组。

服务不可用、名称冲突或接口返回异常时，新会话以不分组降级，继续对话并在响应与 logs/session-last.json 中记录警告；复制诊断也包含本次工作区准备状态。未尝试用未知 API 查找/认领其他目录的同名工作区，此边界待 DSH 提供公开查询契约后处理。不会为绕开冲突生成第二个名字或强行归入普通工作区。

## 首次导入及新增形象（0.12.30）

首次创建角色并导入模型、同角色新增并启用模型、同角色切换已有模型，都会在当前模型加载后进行一次形象互动。分别标记 initial_import / model_added / model_switch，首次建立不会虚构旧形象。批量导入只对实际启用的最后一个模型互动，未显示的模型不假装已经看过。修复缺失资源不属于新增形象。

导入适配弹窗未关闭、参数适配进行中、触摸区草稿仍在调整时等待；跳过适配或完成并退出调整后才进行形象确认，避免并发调用。事件单次消费，普通启动或重复 ready 不触发。AI 总开关、每小时自动额度继续有效，额度 0 在保存/重载后仍保持 0。

形象认知沿用同次图片输入与外观摘要保存流程。模型不支持图片时只使用名称和已有记录，并明确说明尚未建立新的视觉认知；不把编造的外貌当识图结果保存。没有伪造 DSH 用户消息。

## Breeze TTS2 本地语音（0.12.30）

语音与口型 → 语音来源选择“本地 Breeze TTS2”。服务完整地址默认 http://127.0.0.1:7860/v1/audio/speech。先启动独立的 Breeze 推理服务，插件不会下载权重或用桌宠内嵌 Python 安装 PyTorch。把模型放在 voice-models 只是资产管理，不会自动运行推理。

支持官方 PyTorch API 的原生 multipart 字段 text/ref_audio/ref_text/instruction/cfg_scale，以及实现相同原生表单协议的本地服务。参考 WAV ≤8MB，必须填写准确文字稿；纯克隆可留空演绎指令；有指令时请求 cfg_scale=4，无指令为 1。无参考音频时必须填写音色描述。参考音频仅存当前页面内存，重启/切模型后需要重选；文字设置按角色保存，可导出导入。音色 ID 不是此原生接口的必填项，本模式不发送默认 alloy。

“语音试播”可独立验证音频链路，不需要先调用 DeepSeek。确认后启用“AI 回复后自动朗读”。语音 API 与通用本地 JSON 适配器原入口保留。

本地请求只允许回环地址、拒绝重定向，响应限制 16MB。24kHz 单声道 s16le PCM 用标准库加 WAV 头后交给浏览器播放；也接受有效 WAV。409 忙碌时提示用户，不自动反复请求。本版缓冲完整响应后播放，没有实现首包流式播放或服务器推理中断。

Breeze 未返回口型时间轴，本接口不伪造 AIUEO 或 VBridger 逐音素输出；现有时间轴校准入口保留。Breeze 官方权重及自部署输出受独立的研究/非商业许可限制；代码 Apache 许可不等于权重允许商用。使用前核对作者当前许可。

## 自适应台词气泡（0.12.30）

移除台词气泡内的固定高度与滚动条。桌面角色使用独立、无焦点、鼠标穿透且不显示任务栏图标的透明气泡层，按完整文字测量宽高，避让屏幕边缘；不改变角色坐标、角色窗口位置与大小。长台词优先扩宽，工作区空间不足时临时缩小气泡文字；不改写用户保存的字号。靠近屏幕上边缘时优先移到侧面或限制在工作区内，全文可见优先于严格保持在头顶上方。设置页仍保留同样的 DOM 气泡布局作为非桌面环境回退。

对话标签页提供按台词长度自动计时、阅读速度、最短/固定时长、额外停留。默认 300 字/分钟、最短 4 秒、额外 2 秒；这是便于边工作边阅读的可调初值，不宣称所有人的统一阅读标准。中文逐字、英文按单词、标点逐个计数。自动时长为 max(最短时长, 向上取整(计数×60/阅读速度+额外停留))，不再把长台词限制为 60 秒。关闭自动计时后使用固定时长；第三方接口显式传入 ttlMs 的既有协议保留。

这些设置按角色保存并随配置导出/导入，旧配置缺少新增字段时可继续读取。修改计时设置时按本条台词已显示的时间重新计算剩余时长；角色运动和气泡重新定位不延长时间。自然定时陪伴在气泡仍显示时等待，避免长台词未读完就被下一次自动回复覆盖；用户主动的新互动仍可更新台词。

气泡文本通过 textContent 写入，不执行 HTML。气泡随角色窗口移动并跟随置顶状态；重载、退出、调整模式与适配时隐藏，不影响正常穿透工作。音频传输、Breeze 设置、语音播放和口型逻辑保持 0.12.18 原样。

## HTTP 资源与形象记忆异常修复（0.12.30）

将 bubble-layout.js 加入本地 HTTP 静态白名单。构建时同时核对 HTML 引用、发布包成员和 HTTP 白名单，不再只检查文件是否打入包。tests/http-resources.test.py 会实际启动受认证的页面服务器，逐项请求主页面脚本和样式，并检查鉴权/非白名单资源仍被拒绝；tests/bubble-file-resources.test.cjs 另验证独立气泡的 file:// 相对资源与回传，不把两条加载路径混为一谈。

形象摘要、事件回应与 completed 状态现在先持久化，再执行动画、通知、聊天记录渲染和气泡显示。展示异常记录为 UI 警告，不再把已成功收到并保存的回复误判为模型连接失败。计时器先于定位设置；共享计时模块缺失时使用保守的本地后备计时，布局亦有后备逻辑，气泡仍可隐藏。

演出与渲染新增“重新确认当前形象”，可在升级后为当前模型手动补录。它不重新导入、不重新适配、不假装换装；仍受 AI 总开关、自动调用额度与图片能力约束，调用会消耗模型 tokens。失败事件标注 failed/manual；手动确认的新事件可关联 retryOf。完成事件不重发，普通启动/重载不自动补发失败事件，避免额外额度消耗。旧记录不被猜测性改写，图片文件存在并不证明模型曾返回有效视觉摘要。

音频传输、语音设置/播放、口型与配置代码保持 0.12.19 交付版本原样。


## 0.12.30 语音 API 修正

语音 API 改为服务商与模型列表，接入 Breeze / Fish S2 / Qwen3-TTS 的独立协议；API Key 通过桌面进程加密长期保存，不进入角色配置与导出。IndexTTS / AuK 项明确标注本地 SDK 与云接入待定状态，不会发送虚构协议。

Breeze 配置使用 https://api.breeze.blue 与 voc_ 音色，不能使用 /v1/entitlements 合成。旧会话中的密钥需要首次重新填写并保存。语音试播仅使用已保存配置，不自动保存或预先认证，失败不自动重试。

完整调用代码、官方来源、硬件评估和实时模式边界见 docs/tts-api-contracts.md。当前是完整音频返回后播放；未在本次加入本地引擎托管、NAS 接入或实时音频口型同步。

## 0.12.30 语音网络与认证诊断

语音页新增“直连 / 系统代理”，默认直连，只作用于语音请求；不需要全局关代理。新增“验证 Breeze 密钥（不合成音频）”，手动调用官方当前密钥查询。可选测试认证，也可直接试播；认证通过不代表音色权限或语音额度通过。

密钥仍长期加密保存，兼容上一版；增加脱敏指纹、保存时间、格式检查。语音错误落盘并纳入复制诊断，页面保留最近一次失败。Breeze 401 不再误提示地域问题。原有角色、模型、记忆与依赖修复逻辑保留。


## 0.12.30 会话、触摸与输出规则

面板聊天、触摸、自主陪伴和形象确认均走当前角色的同一个 DSH 原生会话。自动事件明确标记软件来源，使用公开 user 通道；没有伪造用户原话，也没有依赖内部 append。事件写入 lc.event.v3，旧 v2/v1 保持可读，不迁移历史。

完整的公共 JSON 格式、类型、范围和演出规则通过固定 required systemPrompt.context 提供，不含历史、即时状态或推理模型名。人格/每皮套真实能力表按会话版本按需附带；即时状态独立发送。默认跟随 DSH 会话选模，指定模型时才使用 LC 的推理上限。更新后请完全退出并重新启动一次 DSH，卸载旧预设；不用删除角色或重建会话。

换装同一轮生成自然台词和内部 appearance.summary；摘要不朗读，也不先生成一份描述让角色复述。自主陪伴不再提示“可不说话”或发送 0.3 发言偏好；空结果明确标为失败，不自动追加一轮付费推理。触摸仍可用动作回应。

触摸末尾防抖默认 250ms，允许 50–5000ms；静止长按不会提前提交，连续操作合并为一次经历。修复浏览器原生计时器被作为对象方法调用导致的 Illegal invocation，并覆盖取消、更改间隔及计时器 ID 为 0 的情况。

包内保留 Python/Electron/Cubism Core 三份离线依赖、校验及修复。修改记录、测试边界和实机验收见 [0.12.30 feedback](docs/RELEASE-0.12.30.md)；当前协议见 [会话事件说明](docs/SESSION-EVENTS.md)。

## 0.12.31 上下文层级

系统层只写通用规范；完整配置注入层包含人格、当前皮套/真实参数/独立口型、所选音频模型及调用格式，可以占内容大头；会话聚焦当前事件。相同 prompt 内调整为配置→补充资料→图片→当前事件，使本轮输入成为最后的回应目标；不是声称有模型注意力百分比控制。具体角色设置仍按 session 隔离附带，未伪装成系统消息。保留现有预算、一次生成和旧记录可读；不新增推理或历史迁移。升级后完整重启一次 DSH，无需清数据。详见 [本轮修改与 feedback](docs/RELEASE-0.12.31.md)。

## 开发测试环境

运行插件所需 Electron/Python/Core 等仍全部内置；JSDOM 是页面测试工具，不是运行依赖，不随生产包安装。开发回归可在外部安装 jsdom，并用 LC_TEST_JSDOM 指向其模块目录执行 Node 测试。生产目录中运行 UI 测试出现 Cannot find module 'jsdom' 说明缺测试环境，不应触发插件依赖修复，也不必给普通用户安装此项。
